# Pinned upstream Hermes NixOS module findings

Scope: upstream [`NousResearch/hermes-agent@5691c9fa47b16a546a5fa418a9e76fddcfbf2701`](https://github.com/NousResearch/hermes-agent/tree/5691c9fa47b16a546a5fa418a9e76fddcfbf2701) only.

## Service paths and identity

- `services.hermes-agent.stateDir` defaults to `/var/lib/hermes`; the module derives `HERMES_HOME` as `${stateDir}/.hermes`. The default service user and group are both `hermes`. [module options and derivation](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/nixosModules.nix#L43-L50) [stateDir option](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/nixosModules.nix#L263-L287)
- With the default `createUser = true`, the system account has `home = cfg.stateDir`, `createHome = true`, and Bash as its login shell. [user declaration](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/nixosModules.nix#L352-L371)
- Native gateway and backend units run as that user/group, set `WorkingDirectory = cfg.workingDirectory`, and set `HOME = cfg.stateDir`, `HERMES_HOME = ${stateDir}/.hermes`, and `HERMES_MANAGED = true`. Thus `HOME` is `/var/lib/hermes` by default, not the `.hermes` directory; Hermes state is selected by the explicit `HERMES_HOME` environment variable. [unit service configuration](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/nixosModules.nix#L211-L240) [environment renderer](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/moduleCommon.nix#L1077-L1091)
- The CLI resolves its active home in this order: context-local override, `HERMES_HOME`, then platform default; on POSIX that default is `$HOME/.hermes`. It expands `~` and environment references in an explicitly supplied `HERMES_HOME`. [resolver](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/hermes_constants.py#L52-L69) [precedence](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/hermes_constants.py#L194-L201)

## Directory creation and layout

- NixOS tmpfiles and activation create `stateDir`, `stateDir/.hermes`, `stateDir/home`, and the working directory. The first three state paths use group-writable setgid mode `2770` (except `stateDir/home`, mode `0750`); the module also creates `.hermes/cron`, `sessions`, `logs`, `memories`, and `plugins`. [tmpfiles and activation setup](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/nixosModules.nix#L443-L497) [state subdirectory list](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/moduleCommon.nix#L1171-L1178)
- The CLI's managed-mode initializer does **not** create a missing home or the required `cron`, `sessions`, `logs`, and `memories` directories; it requires them to exist. It does create `logs/curator` and seeds `SOUL.md`. NixOS activation must therefore establish the state tree before the managed CLI starts. [managed initializer](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/hermes_cli/config_home.py#L56-L80)
- Nix settings are merged into `.hermes/config.yaml`; `hermesHomeFiles` are installed relative to `HERMES_HOME`, while `documents` target the working directory. The default NixOS working directory is `${stateDir}/workspace`. [configuration and home-file installation](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/moduleCommon.nix#L806-L911) [working-directory default](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/nixosModules.nix#L253-L259)

## `.env` and `environmentFiles`

- When `environment` or `environmentFiles` is nonempty, activation writes a fresh `$HERMES_HOME/.env` from `environment` and then appends each readable file. `environmentFiles` is a list of runtime strings, deliberately not Nix paths, to avoid copying secrets into the Nix store; unreadable inputs only emit a warning. The result is mode `0640` and owned by the service user/group. [option contract](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/moduleCommon.nix#L291-L320) [merge script](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/moduleCommon.nix#L763-L792) [activation invocation and ownership](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/moduleCommon.nix#L890-L897)
- The native systemd units intentionally do **not** use systemd `EnvironmentFile=`. They only receive the fixed unit environment; the gateway reads `.hermes/.env` during Python startup. [unit behavior](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/nixosModules.nix#L563-L611)
- `load_hermes_dotenv()` loads `<HERMES_HOME>/.env` with override enabled, so it overrides stale shell exports. A project `.env` only fills gaps if the home `.env` exists (otherwise it overrides); `.op.env` only fills gaps; the managed overlay loads last. [load order and precedence](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/hermes_cli/env_loader.py#L652-L782)

## Migration-relevant settings

- Preserve the entire configured `stateDir`—not merely its `.hermes` subdirectory—because the module uses `${stateDir}/workspace` by default and reserves `${stateDir}/home`; the managed runtime state itself is under `${stateDir}/.hermes`. [path declarations](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/nixosModules.nix#L443-L452)
- Set `environmentFiles` to runtime secret paths and keep secrets out of `environment`; when either option is configured, activation rebuilds `.env` on each deployment, so manual edits to that generated file are not durable. [option semantics](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/moduleCommon.nix#L291-L320) [rebuild implementation](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/moduleCommon.nix#L763-L791)
- `addToSystemPackages = true` exports the same derived `HERMES_HOME` to interactive shells, avoiding a separate per-user default `$HOME/.hermes` store. [host CLI configuration](https://github.com/NousResearch/hermes-agent/blob/5691c9fa47b16a546a5fa418a9e76fddcfbf2701/nix/nixosModules.nix#L374-L381)
